# Subscription journey

Mode: Operate. Extension of the existing Zentra account and native settings; no new visual world or global token changes.

## Direction contract
THESIS: One company, one subscription view. The owner can understand existing access and the future price before changing a plan.
OWN-WORLD: Existing quiet white account panels, system UI type, deep green actions, muted separators; native dark theme uses distinct charcoal surfaces.
STORY: Read the active products, renewal, seats and quota; act only when needed; finish a short four-step startup.
FIRST VIEWPORT: Company and plan heading, price/date/team facts, then three compact product rows. Remaining analyses use one bar and an alert at 80 percent. Billing and plan details follow; no promotional hero.
FORM: Precisely specified local extension, code-led. No concept seed, decision board or comp applies. Progressive disclosure reveals the dated change summary and explicit confirmation.
FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Evidence scope
The shared React view is used by the site and Tauri app. Screenshots use explicitly fictional data and the real component. Browser viewport screenshot stitching is malformed, so review uses valid individual viewport captures at top and bottom instead of stitched full-page files. Native rendering is checked in the responsive shared view; no iOS simulator is available on this Windows host.
Trial: 14 days, 3 Gestion people including owner, 250 Support analyses, no card or automatic payment. Financial changes stay in the authenticated owner website and start after the latest verified paid period. No live customer subscription is changed by test fixtures.
