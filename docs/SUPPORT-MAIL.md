# Connexion Infomaniak dans Zentra Support

Dans Connexions, choisir Infomaniak Mail, saisir l’adresse exacte de la boîte et une clé API du compte Infomaniak avec le droit `workspace:mail`. La clé est validée contre la liste des boîtes du compte et la présence du dossier INBOX, puis chiffrée avec le coffre Support existant. Ne pas envoyer la clé par messagerie.

Les messages de la boîte de réception arrivés depuis la connexion sont importés par pages de 20, avec un identifiant stable propre à la boîte, au dossier et au message. Chaque analyse consomme le quota Support habituel. Les catégories sont prêtes dès la connexion ; les modes automatique et validation de l’espace restent applicables. Le classement se fait dans Support : aucun envoi, déplacement, suppression ou changement du statut lu chez Infomaniak. Les pièces jointes ne sont pas importées et imposent une validation humaine. Remplacer la clé conserve le curseur et l’historique.

Le traitement serveur est appelé par `.github/workflows/support-mail-sync.yml` dans le dépôt GitHub `leartshbj1/zentra`, branche par défaut. Le secret `SUPPORT_MAIL_SYNC_TOKEN` doit correspondre au secret Sites de même nom. Il ne donne aucun accès à la lecture des tickets, seulement à l’exécution des synchronisations dues. Ne pas utiliser une automatisation Codex personnelle pour ce service produit. Le planning cible cinq minutes ; GitHub Actions peut retarder ses exécutions. Le bouton Synchroniser maintenant permet une récupération immédiate. GitHub peut désactiver les plannings d’un dépôt public après une longue période d’inactivité ; vérifier leur état dans Actions si la dernière récupération cesse d’avancer.

Un bail D1 évite deux récupérations simultanées. Les pages sont parcourues jusqu’au bout, puis le parcours reprend depuis le début pour absorber les changements de pagination pendant l’arrivée de messages. Une erreur de lecture conserve la page en cours ; les messages déjà importés sont dédupliqués. Les analyses interrompues sont reprises, avec trois tentatives automatiques maximum avant reprise manuelle. Les boîtes sont choisies par échéance, pour éviter qu’une boîte en erreur bloque les autres. Une période Support expirée suspend les lectures ; les messages toujours présents chez Infomaniak sont récupérés après réactivation.

Contrat API vérifié dans le [client officiel Infomaniak](https://github.com/Infomaniak/mcp-server-mail/blob/main/src/mail-client.ts) : liste des boîtes, dossiers, messages avec `thread=off`, lecture d’un message, authentification Bearer. L’hôte est fixe, les redirections sont refusées et aucune réponse brute du fournisseur n’est exposée.

Validation : tests de bout en bout sur SQLite avec Infomaniak simulé, protection du traitement serveur, isolation des espaces, chiffrement, pagination, doublons, interruption/reprise, reconnexion, validation humaine et expiration. La connexion d’une vraie boîte exige sa clé saisie dans le formulaire et un mail reçu ensuite.
